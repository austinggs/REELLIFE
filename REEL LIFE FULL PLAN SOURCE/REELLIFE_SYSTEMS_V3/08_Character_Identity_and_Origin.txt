REELLIFE — SYSTEM 08: CHARACTER IDENTITY & ORIGIN
===================================================
Status: Approved architecture

ROLE
----
Defines persistent person identity, origins, birth context, and identity history.

OWNS
-----
- immutable PersonId
- identity fields
- name structure
- birth metadata
- parentage references
- origin context
- appearance foundation
- generation metadata
- identity history

DOES NOT OWN
------------
- personality
- skills
- development outcomes
- social reputation
- legal rule interpretation
- life decisions

MODEL / STATE
-------------
- PersonId survives name changes, migration, death, save/load, and control transfer
- Names are attributes, not identity
- Origin distinguishes biological origin, nationality, citizenship, culture, residence, and household origin
- Parentage supports biological, legal, adoptive, guardian, unknown, and multiple configurations where content rules allow

RULES / BEHAVIOR
-----------------
- Birth creates the person and links to parents/household/legal/admin/development initialization through events
- Appearance foundations use inheritance plus controlled variation
- Player and NPCs use the same Person architecture
- Legal identity references are distinct from simulation identity
- Origin is a condition set, not destiny

SYSTEM INTERACTIONS
-------------------
- Uses Geography for birthplace and location
- Feeds Aging, Family, Legal Identity, Life Continuity, Cognition, and culture
- Control transfer after death changes player agency without changing PersonId/history

TESTING / QUALITY
-----------------
- Test identity persistence, name changes, migration, ambiguous/unknown parentage, adoption, multiple caregivers, descendant control transfer, and deterministic generation

SHARED ARCHITECTURAL LAWS
--------------------------
1. One authoritative owner for every persistent state field.
2. Commands express intent; events represent occurrences; consequences change state.
3. UI never directly mutates simulation state.
4. Information/knowledge is distinct from world truth.
5. Legal identity is distinct from simulation identity.
6. Organization and relationship structures are universal, not duplicated per domain.
7. Time has one authoritative clock.
8. Authoritative RNG is seeded, serialized, and reproducible.
9. Derived state remains derived.
10. Simulation resolution may change detail, never causal truth.
11. Origin influences conditions/opportunities, not destiny.
12. Legacy propagates through concrete systems, not arbitrary hidden modifiers.
13. .reel is the native persistent world/save format.

OUTCOME / CAUSALITY CHECK
--------------------------
This system must participate in the governing loop: CONDITIONS -> DECISIONS -> EVENTS -> CONSEQUENCES -> NEW CONDITIONS.

CORE PRINCIPLE
---------------
A person remains the same persistent entity even as names, locations, relationships, and legal circumstances change.

IMPLEMENTATION NOTE
-------------------
Keep authoritative state single-owned, serializable, deterministic where configured, and separated from UI presentation. Cross-system effects should travel through Commands, Events, and explicit consequence handlers.

END OF SYSTEM SPEC
