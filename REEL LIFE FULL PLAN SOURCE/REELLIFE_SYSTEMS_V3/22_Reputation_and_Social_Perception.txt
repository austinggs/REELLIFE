REELLIFE — SYSTEM 22: REPUTATION & SOCIAL PERCEPTION
======================================================
Status: Approved architecture

ROLE
----
Models how people and organizations are perceived from observed behavior, information, demonstrations, endorsements, records, rumors, and social history.

OWNS
-----
- reputation state
- perceived characteristics
- credibility
- status perception
- demonstrated reputation
- public/private reputation
- observer/community perception
- evidence and allegations
- endorsements/recommendations
- reputation change/decay/repair
- institutional reputation

DOES NOT OWN
------------
- objective behavior
- raw information propagation
- cognition mechanics
- personality
- relationship state
- skill truth
- legal adjudication

MODEL / STATE
-------------
- Core chain: Truth -> Information -> Belief -> Reputation -> Behavior
- Reputation is observer-relative, multidimensional, contextual, evidence-based, and fallible
- Evidence quality considers source reliability, directness, corroboration, recency, and context
- Credibility and status are domain/context dependent

RULES / BEHAVIOR
-----------------
- Public and private reputation can differ
- Demonstrated competence can create reputation without changing underlying skill
- Rumors belong to Information and are consumed as claims
- False reputation can persist when socially supported
- Reputation decays without automatically erasing history
- Repair can come through apology, restitution, correction, repeated positive behavior, endorsements, institutional findings, and time
- Association effects are contextual, not universal guilt by proximity

SYSTEM INTERACTIONS
-------------------
- Consumes Cognition/Information and feeds Relationships, Employment, Finance, Organizations, Social Systems, and legal/social response
- Reputation profiles are sparse and observer/community based for performance

TESTING / QUALITY
-----------------
- Test misinformation, observer disagreement, rumor correction, reputation repair, local vs portable reputation, institutional reputation, and cascading effects

SHARED ARCHITECTURAL LAWS
--------------------------
1. One authoritative owner for every persistent state field.
2. Commands express intent; events represent occurrences; consequences change state.
3. UI never directly mutates simulation state.
4. Information/knowledge is distinct from world truth.
5. Legal identity is distinct from simulation identity.
6. Organization and relationship structures are universal, not duplicated per domain.
7. Time has one authoritative clock.
8. Authoritative RNG is seeded, serialized, and reproducible.
9. Derived state remains derived.
10. Simulation resolution may change detail, never causal truth.
11. Origin influences conditions/opportunities, not destiny.
12. Legacy propagates through concrete systems, not arbitrary hidden modifiers.
13. .reel is the native persistent world/save format.

OUTCOME / CAUSALITY CHECK
--------------------------
This system must participate in the governing loop: CONDITIONS -> DECISIONS -> EVENTS -> CONSEQUENCES -> NEW CONDITIONS.

CORE PRINCIPLE
---------------
Reputation is socially distributed belief, not a universal morality score.

IMPLEMENTATION NOTE
-------------------
Keep authoritative state single-owned, serializable, deterministic where configured, and separated from UI presentation. Cross-system effects should travel through Commands, Events, and explicit consequence handlers.

END OF SYSTEM SPEC
