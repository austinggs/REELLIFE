REELLIFE — SYSTEM 03: RANDOMNESS, SEEDS & SCENARIO RESOLUTION
===============================================================
Status: Approved architecture

ROLE
----
Provides controlled uncertainty, seeded reproducibility, and scenario outcome resolution.

OWNS
-----
- master/world/scenario seeds
- RNG streams and stream state
- distribution utilities
- weighted outcomes
- hazard/probability resolution
- replay metadata
- RNG versioning and serialization

DOES NOT OWN
------------
- eligibility rules
- domain decisions
- domain state changes
- using randomness as a substitute for simulation logic

MODEL / STATE
-------------
- Hierarchical seeds and independent RNG streams reduce accidental cross-system coupling
- ResolutionObject captures applicability, conditions, candidates, probabilities/weights, selected outcome, and RNG/debug metadata
- Eligibility is evaluated separately from probability
- Probability is interpreted as uncertainty among valid outcomes

RULES / BEHAVIOR
-----------------
- Authoritative simulation never uses uncontrolled Math.random()
- Useful distributions include uniform, normal, log-normal, exponential, Poisson, Bernoulli, and binomial where appropriate
- Inheritance/generation combines parental contribution, variation, development, and environment rather than pure random assignment
- Hazard rates support time-dependent events and tick-invariant resolution
- Invalid outcomes and all-zero probability sets must be handled explicitly

SYSTEM INTERACTIONS
-------------------
- Used by identity generation, development, decisions, events, markets, world variation, and rare events
- Save/load preserves RNG state so reloading does not silently change future outcomes
- Simulation resolution changes must preserve deterministic outcomes when deterministic mode applies

TESTING / QUALITY
-----------------
- Test determinism, stream independence, distribution sanity, boundaries, serialization, replay, and tick/speed invariance

SHARED ARCHITECTURAL LAWS
--------------------------
1. One authoritative owner for every persistent state field.
2. Commands express intent; events represent occurrences; consequences change state.
3. UI never directly mutates simulation state.
4. Information/knowledge is distinct from world truth.
5. Legal identity is distinct from simulation identity.
6. Organization and relationship structures are universal, not duplicated per domain.
7. Time has one authoritative clock.
8. Authoritative RNG is seeded, serialized, and reproducible.
9. Derived state remains derived.
10. Simulation resolution may change detail, never causal truth.
11. Origin influences conditions/opportunities, not destiny.
12. Legacy propagates through concrete systems, not arbitrary hidden modifiers.
13. .reel is the native persistent world/save format.

OUTCOME / CAUSALITY CHECK
--------------------------
This system must participate in the governing loop: CONDITIONS -> DECISIONS -> EVENTS -> CONSEQUENCES -> NEW CONDITIONS.

CORE PRINCIPLE
---------------
Randomness should model uncertainty around rules, not replace the rules.

IMPLEMENTATION NOTE
-------------------
Keep authoritative state single-owned, serializable, deterministic where configured, and separated from UI presentation. Cross-system effects should travel through Commands, Events, and explicit consequence handlers.

END OF SYSTEM SPEC
