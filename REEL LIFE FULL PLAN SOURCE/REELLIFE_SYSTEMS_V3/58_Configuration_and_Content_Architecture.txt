REELLIFE — SYSTEM 58: CONFIGURATION & CONTENT ARCHITECTURE
============================================================
Status: Approved architecture

ROLE
----
Separates simulation engine mechanics from content, rules, world configuration, game modes, difficulty, and historical setup.

OWNS
-----
- game-mode configuration
- difficulty configuration
- content registries
- rule configuration
- scenario/world setup
- historical configuration
- content/schema versioning
- mod/content boundaries

DOES NOT OWN
------------
- runtime world state
- authoritative event state
- UI implementation
- domain algorithm implementations

MODEL / STATE
-------------
- Engine = how simulation works; Content = what exists; Rules = how world behaves; Configuration = scenario setup
- Data-driven content covers occupations, skills, education, foods, items, vehicles, buildings, businesses, technology, laws, holidays, culture, diseases, weather, organizations, currencies, and similar definitions
- Modes can include normal, historical, alternate-history, sandbox, scenario, challenge, and custom world

RULES / BEHAVIOR
-----------------
- Difficulty can alter uncertainty, resources, consequences, constraints, and information without breaking fundamental causal logic
- Historical configuration sets era, countries, technology, laws, institutions, economy, culture, and population context
- Content is versioned separately from engine/simulation to protect .reel compatibility
- Modding should extend content through explicit interfaces rather than engine rewrites

SYSTEM INTERACTIONS
-------------------
- Every domain system reads configuration/content definitions rather than scattered constants
- Persistence stores relevant content/rule versions

TESTING / QUALITY
-----------------
- Test missing/invalid content, version mismatches, mode configuration, historical prerequisites, difficulty effects, and save compatibility

SHARED ARCHITECTURAL LAWS
--------------------------
1. One authoritative owner for every persistent state field.
2. Commands express intent; events represent occurrences; consequences change state.
3. UI never directly mutates simulation state.
4. Information/knowledge is distinct from world truth.
5. Legal identity is distinct from simulation identity.
6. Organization and relationship structures are universal, not duplicated per domain.
7. Time has one authoritative clock.
8. Authoritative RNG is seeded, serialized, and reproducible.
9. Derived state remains derived.
10. Simulation resolution may change detail, never causal truth.
11. Origin influences conditions/opportunities, not destiny.
12. Legacy propagates through concrete systems, not arbitrary hidden modifiers.
13. .reel is the native persistent world/save format.

OUTCOME / CAUSALITY CHECK
--------------------------
This system must participate in the governing loop: CONDITIONS -> DECISIONS -> EVENTS -> CONSEQUENCES -> NEW CONDITIONS.

CORE PRINCIPLE
---------------
The engine should not be rewritten merely to add new content or a new world configuration.

IMPLEMENTATION NOTE
-------------------
Keep authoritative state single-owned, serializable, deterministic where configured, and separated from UI presentation. Cross-system effects should travel through Commands, Events, and explicit consequence handlers.

END OF SYSTEM SPEC
