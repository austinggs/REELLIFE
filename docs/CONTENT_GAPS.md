# Content Gaps & Provisional Decisions

The World Bible defers exact economic/civic content by design (no canonical
GDPs, currencies, company names, city populations, religious shares, named
wars). This file logs every place the implementation filled a gap with a
provisional decision, so the choice is visible and revisable instead of hidden
in code. Nothing here is canon.

## Provisional content

| Gap | Provisional decision | Where |
| --- | --- | --- |
| No canonical currency defined | Single provisional currency `AUR` ("Aurelian mark") used for all Money values | seeded through fixtures/tests; `primitives/money.ts` is currency-agnostic |
| No canonical calendar detail beyond the epoch | WorldTime = integer minutes since 1900-01-01T00:00Z; Aurelian calendar derived by `time/calendar.ts`; sim start defaults to 1 Jan 2042 | `primitives/time.ts`, `time/calendar.ts` |

## Mechanics the M2 slice deliberately does not have yet

| Topic | Current behaviour | Owning system / milestone that resolves it |
| --- | --- | --- |
| Job applications vs offers | `employment.apply` hires directly. There is no offer state for `employment.accept` to accept, so `accept` is folded into `apply` until System 24 matures | System 24 (Employment) — M5 polish |
| Payroll | `employment.work_shift` records the shift as an activity only; wages move by explicit `finance.transfer` with category `"wage"`. No automatic payroll runs | System 24/25 — M5 |
| Overdrafts / arrears | Finance permits negative balances (rent arrears are load-bearing in the job-loss scenario). No overdraft rules, interest, or collections | System 25 — M5 |
| Starting a conflict | No command: conflict is not something an actor *chooses* in M2. Tests record it through the relationships engine directly, with the gap stated in the test header | System 21 (Conflict) — M6 |
| NPC initiative | The decisions engine (System 17) evaluates options but nothing ticks it autonomously; NPC behaviour in scenarios is driven by explicit `origin: "npc"` commands | System 17 wiring — late M2/M3 |
| Authority | Commands declare no `authorityRequirement` yet; the authority evaluator exists (`primitives/authority.ts`) but domain commands don't gate on it | System 20/48 — M6 |
| `world.load` hot-swap | A `world.load` command cannot replace the running Simulation mid-dispatch. It validates, emits `world.load_requested`, and the platform performs the swap via `Simulation.load` + `bootstrapLoadedSimulation` | documented on the command; the M3 app performs the swap in `src/app/session/worldLoad.ts` |
| Save-slot listing vs corrupt bytes | `SaveStore.listSlots()` reads each slot's raw text and calls `slotInfoOf`, so a slot whose bytes are not a JSON `.reel` document makes the whole call throw (there is no metadata to return) and every other slot disappears with it. The M3 Settings screen therefore reports "saved worlds could not be listed" with the store's own message instead of showing a false empty list; a slot that parses but fails validation *is* listed as `corrupt` with the validator's explanation and cannot be loaded | System 06 — a store-level "unreadable slot" entry in `ReelSlotInfo`/`listSlots()` is the follow-up (deliberately not invented in M3, since it changes the persistence contract) |

| No canonical media, platforms or rumour networks (System 49) | Two notice boards the slice's own content implies (a dockside shift board, a mill market board), seven organization/place nodes and one node per resident. **No claim is seeded at all** — a claim needs an author and an audience, and inventing both at seed time would put words in residents' mouths before anyone has spoken. | Propagation is deterministic and factor-weighted (System 49) | `carriedValue` = .4 source credibility + .3 novelty + .3 emotional charge, times channel reach, times node openness (.6 when linked, .3 when not), with .6 hop decay and .8 retell decay per retelling; a claim below 0.15 does not reach a node. **No RNG is consulted**, so a rumour's spread is reproducible — which is not how rumours work in life, and is the price of being able to assert that one spread. | Exposure is not belief (System 49) | An `Exposure` records that a node was reached. Belief, distrust and interpretation are System 15/22's, and nothing here stores what anyone concluded. | `CirculatingClaim`, not `InformationClaim` (System 49) | The kernel primitive `InformationClaim` (`primitives/information.ts`) is the *observer-facing* claim a projection hands the UI, with `knownBy`/visibility/actuality. The two are related but not identical, so the system-side type is named `CirculatingClaim` rather than shadowing the primitive | `src/engine/information/types.ts` |
| Moderation cannot launder unverified into suppressed (System 49) | `isPropagatable` only blocks a claim on an explicit `removed` record. An unverified claim still propagates: the absence of verification is a fact about status, not a licence to suppress, and conflating the two is how a rumour engine becomes a censorship engine. Downranking (0.5×) weakens without stopping | `src/engine/information/engine.ts` `isPropagatable` |

## Provisional decisions introduced with M6 (System 51)

| Gap | Provisional decision | Where |
| --- | --- | --- |
| **No technology era table exists in this repository (System 51)** | The World Bible is said to author 11 technology eras and 9 development stages. `canon.ts` contains 8 history eras and 17 active world developments, and **no technology era data at all**. Encoding an eleven-row table from memory would be inventing canon, so none is encoded. Six slice-local technologies are authored instead, each derived from content the slice already has (a mill that bakes overnight, a berth with pilotage, rules that cap a crane load) | `src/content/aurelia/technologies.ts` |
| Adoption weights (System 51) | `ADOPTION_WEIGHTS` covers the spec's own nine factors — price 0.2, infrastructure 0.15, network 0.12, knowledge 0.12, compatibility 0.1, institutions/culture/geography 0.08 each, regulation 0.07. **Additive, not multiplicative**, on purpose: a mill adopted in spite of an unsympathetic local culture is a real outcome, and a product of nine numbers could not express it. Not calibrated against anything | `src/engine/technology/engine.ts` `ADOPTION_WEIGHTS` |
| The denominator of diffusion is supplied, not derived (System 51) | `diffusion(technologyId, eligible)` takes the eligible population from the caller. The engine has no claim on who could have adopted something, and a rate without a denominator is a number with no meaning | `src/engine/technology/engine.ts` `diffusion` |
| A forward reference is a registration error (System 51) | `registerTechnology` refuses a prerequisite that is not already catalogued, so an anachronism must be created deliberately. `availability` *also* checks invention dates transitively, so a state loaded from a save file cannot smuggle one in either | `src/engine/technology/engine.ts` `registerTechnology`, `availability` |
| Anachrony permission is a visible record (System 51) | The spec permits running ahead of the sequence "unless scenario configuration explicitly permits it". That permission is a `permission` field **with a mandatory reason**, on by default false, rather than a hidden flag — a world whose timeline is now a scenario decision says so in one line | `src/engine/technology/engine.ts` `setAnachronyPermission` |
| Obsolescence applies from its date, not retroactively (System 51) | Found by a test: a technology superseded *next year* was already reading as `retired` today, which would erase the present tense of how the slice works. `retired` is now `obsolescence.at <= at` | `src/engine/technology/engine.ts` `availability` |
| `TechnologyAvailability`, not `Availability` (System 51) | System 44 already exports an `Availability` for a different question (what a *place* makes culturally available to an arrival). Two exported types with opposite meanings invite reading the wrong one, so System 51's is named for its system | `src/engine/technology/types.ts` |
| Nothing is adopted at seed time (System 51) | The seed registers the catalogue and no adoptions. Invented, available and adopted are three gates, and granting the slice's organizations its whole toolkit at world start would collapse all three into one assumption | `src/engine/kernel/sliceSeed.ts` |
